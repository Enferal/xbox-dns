# Установка на сервер

Проект: https://github.com/Enferal/xbox-dns. Код под лицензией MIT: [LICENSE](LICENSE).

Приставка или телефон использует ваш сервер как DNS. Имена из списка сервер называет своими. Сайт тогда видит адрес сервера, а не домашний. Остальной интернет идёт как раньше. Интернет самого сервера скрипт не меняет.

Куда смотреть дальше:

- этот файл — поставить службу и включить Xbox и UFC 5
- [README_EASY.md](README_EASY.md) — то же самое короче и спокойнее
- [README_STUPID.md](README_STUPID.md) — по шагам, если команды непривычны
- [OPENWRT.md](OPENWRT.md) — домашний роутер на OpenWrt
- [ROUTER.md](ROUTER.md) — приставка получает адрес сервера, а соединение до него не доходит

Ниже `АДРЕС_VPS` — адрес сервера. Его печатает установщик в строке `На устройстве укажите DNS`. `АДРЕС_ДОМА` — белый адрес дома. В журнале он стоит после `клиент=`.

## Что нужно на сервере

Ubuntu 22.04 или 24.04, вход root. Установщик сам поставит `python3`, `iproute2`, `ca-certificates`, `bind9-dnsutils`, `ufw` и `git`, если их нет. На экране будет `Ставлю недостающее` или `Все нужные пакеты уже стоят`. Другую систему он не ставит.

`git` нужен раньше, чтобы скачать проект. Его ставит команда установки ниже.

Перед установкой порты 53, 80 и 443 должны быть свободны:

```bash
ss -tulpn 'sport = :53 or sport = :80 or sport = :443'
```

Строка `127.0.0.53:53` — это локальный DNS Ubuntu, она не мешает. Строка `*:443` или `0.0.0.0:443` значит, что порт уже занят другой программой. Пока она работает, DNS поднимется, а сайты через сервер не откроются.

## Установка

На сервере:

```bash
ssh root@АДРЕС_VPS
apt-get update
apt-get install -y git
git clone https://github.com/Enferal/xbox-dns.git /opt/egress-proxy
cd /opt/egress-proxy
sh deploy/install-native.sh
```

Первая строка установщика: `Установщик egress-proxy. Пустой ALLOW_CLIENTS пускает всех.` Если вместо неё сразу пошёл список пакетов, запущен другой скрипт.

Скрипт ставит службу `egress-proxy` и берёт имена Xbox из `config/allow-destinations.xbox.txt`. Входящий SSH он открывает всегда. Порт 53 и порты из `PROXY_PORTS` в первый раз открывает для всех. Сначала в `PROXY_PORTS` только 80 и 443.

Если правила для 53, 80 и 443 уже есть, скрипт показывает их и спрашивает.

- Enter оставляет файрвол как есть. Новые порты он при этом сам не добавляет.
- `адреса` убирает разрешения для всех и оставляет правила, в которых указан адрес.
- `все` заново открывает 53 и порты из `PROXY_PORTS` для всех.

В конце будет строка `На устройстве укажите DNS:` и адрес сервера. Его вписывают в DNS приставки.

Повторный запуск `sh deploy/install-native.sh` снова задаёт вопросы и перезаписывает `/etc/egress-proxy/egress.env`. Для обычного обновления программы он не нужен. Обновление без вопросов:

```bash
cd /opt/egress-proxy
git pull
install -m 0755 scripts/egress_proxy.py /usr/local/lib/egress-proxy/egress_proxy.py
systemctl restart egress-proxy
```

### Вопросы установщика

У каждого вопроса есть пример и строка «Сейчас». Enter оставляет «Сейчас».

Если настройки уже лежат в `/etc/egress-proxy`, первый вопрос: `Удалить прошлые настройки? [y/N]`. Enter сохраняет `egress.env`, список имён и `exit-ips.txt`. `y` стирает эти три файла и кладёт примеры заново.

`DNS_UPSTREAM` устроен иначе. Enter подставляет DNS самого сервера из его настроек. Адреса `127.0.0.53` туда не попадают. Своего DNS на сервере нет — останется `1.1.1.1,8.8.8.8`. Старый список скрипт покажет строкой «В файле сейчас». Чтобы сохранить его, введите его руками.

| Вопрос | Что означает | Enter |
| --- | --- | --- |
| `LISTEN_IP` | На каком адресе принимать клиентов. `0.0.0.0` — на всех, в том числе на адресе этого сервера. | как сейчас, или `0.0.0.0` |
| `DNS_PORT` | Порт DNS. Его указывают на приставке. | `53` |
| `PROXY_PORTS` | Какие TCP-порты принимать. Несколько портов через запятую. Диапазон пишется так: `15000-15099`. | `80,443` |
| `DNS_UPSTREAM` | Куда сервер сам спрашивает настоящие адреса сайтов. | DNS этого сервера |
| `MAX_WILDCARD_DEPTH` | Сколько частей слева покрывает имя из списка. `4` хватает для `a.b.c.d.example.com`. | `4` |
| `ANSWER_TTL` | Сколько секунд приставка помнит ответ. | `60` |
| `ALLOW_CLIENTS` | Кто может спрашивать этот DNS. Пусто — любой адрес. Знак `-` тоже пускает всех. | пусто |

## Кто может подключаться

Файл: `/etc/egress-proxy/egress.env`.

Пустая строка `ALLOW_CLIENTS=` пускает всех. Чтобы пускать только свои адреса:

```bash
ALLOW_CLIENTS=203.0.113.8,198.51.100.0/24
systemctl restart egress-proxy
```

Чужой адрес увидит в журнале `Отказ DNS клиенту …`. Число в этой строке — тот адрес, который можно дописать в список.

## Приставка

В сети приставки укажите DNS из последней строки установки. Второй DNS оставьте пустым. Прокси, VPN и «безопасный DNS» для неё выключите.

На обычном роутере этого достаточно: до сервера должны проходить UDP и TCP 53, TCP 80 и TCP 443. Роутер OpenWrt дополнительно настраивается по [OPENWRT.md](OPENWRT.md).

Проверка на самом сервере:

```bash
dig +short @127.0.0.1 user.auth.xboxlive.com A
```

В ответе должен быть адрес этого сервера. С компьютера в той же сети, что и приставка:

```bash
nslookup user.auth.xboxlive.com АДРЕС_VPS
```

После смены DNS выдерните питание приставки на 10 секунд. Иначе она помнит старые адреса.

## Какие имена идут через сервер

Список: `/etc/egress-proxy/allow-destinations.txt`.

Строка `xboxlive.com` покрывает и само имя, и имена внутри него, например `user.auth.xboxlive.com`. В примере также есть `xbox.com`, `xboxservices.com`, `gamepass.com`, `bing.com`, `microsoft.com`, `akamai.net`, `akamaized.net`, `windowsupdate.com`, `live.com`, `microsoftonline.com`, `msauth.net` и `msftauth.net`. Это общие зоны: через сервер пойдёт любой сайт на таком имени. Лишнюю строку можно удалить.

Закачка игр в этот список не входит. Имена из `/etc/egress-proxy/direct-destinations.txt` (`dl.delivery.mp.microsoft.com`, `assets1.xboxlive.com` и соседние) получают настоящий адрес сети доставки. Файл качается с домашнего адреса. В журнале это строка `закачка напрямую`.

Три имени служба обрабатывает сама:

- `www.msftconnecttest.com` и `ipv6.msftconnecttest.com` — проверка связи. Ответ отдаёт сервер, Microsoft домашний адрес не видит.
- `dns.msftncsi.com` — фиксированный адрес Microsoft, соединения туда нет.
- `xbox.ipv6.microsoft.com` — настоящий адрес Microsoft. Приставка открывает его только так.

После правки списка:

```bash
systemctl restart egress-proxy
```

Для Xbox служба слушает TCP 80 и 443. Голос и часть мультиплеера идут по UDP и через эту службу не проходят.

## UFC 5

Синхронизация UFC 5 ходит на серверы EA и в облачное сохранение Xbox. Имена `ea.com` и `blob.core.windows.net` уже есть в списке. Куски имён `spring18`, `gosca18` и `ext-…blaze` меняются, поэтому в списке вся зона `ea.com`.

Порты у EA тоже свои. Редиректор сообщает приставке, на какой номер blaze идти в этот раз. В захвате уже были 15001, 15007 и 15025, все они внутри 15000–15099.

В `/etc/egress-proxy/egress.env`:

```bash
PROXY_PORTS=80,443,42130,44326,15000-15099
```

| Имя | Порт | Зачем приставке |
| --- | --- | --- |
| `gcs.ea.com`, `freeform-river.data.ea.com`, `collector.errors.ea.com` | 443 | учётная запись и отчёты об ошибках |
| `titlestorage….blob.core.windows.net` | 443 | облачное сохранение |
| `….gosredirector.ea.com` | 42130 | говорит, где сейчас blaze |
| `gosca….ea.com` | 44326 | сертификат EA |
| `….blaze.ea.com` | 15000–15099 | сам игровой сервер |

Запись `15000-15099` понимает свежий `egress_proxy.py`. Если служба старая, сначала выполните обновление из раздела «Установка», потом меняйте строку.

Если файрвол пускает на сервер только дом, откройте те же порты с домашнего адреса:

```bash
ufw allow from АДРЕС_ДОМА to any port 42130 proto tcp
ufw allow from АДРЕС_ДОМА to any port 44326 proto tcp
ufw allow from АДРЕС_ДОМА to any port 15000:15099 proto tcp
systemctl restart egress-proxy
```

Повторный установщик эти порты сам не добавит, пока для 53, 80 и 443 уже есть правила и на вопросе вы нажимаете Enter. Строку `PROXY_PORTS` правьте в файле.

В журнале удачная синхронизация выглядит так:

```text
Прокси spring18.gosredirector.ea.com:42130 -> … с адреса АДРЕС_VPS
Прокси gosca18.ea.com:44326 -> … с адреса АДРЕС_VPS
Прокси ext-3-252-47-140.blaze.ea.com:15007 -> … с адреса АДРЕС_VPS
```

Номер после `blaze.ea.com` будет другим, из диапазона 15000–15099. Если в журнале есть `DNS …blaze.ea.com A -> АДРЕС_VPS`, а строки `TCP входящий` нет, приставка стучится в порт, которого служба не слушает. В эту же минуту на сервере:

```bash
tcpdump -n -i any 'tcp[tcpflags] & tcp-syn != 0 and src host АДРЕС_ДОМА and dst port not 22 and dst port not 53 and dst port not 80 and dst port not 443 and dst port not 42130 and dst port not 44326'
```

В строке будет `АДРЕС_ДОМА > АДРЕС_VPS.НОМЕР`. Этот номер добавьте в `PROXY_PORTS` и в `ufw`, затем `systemctl restart egress-proxy`. Остановить `tcpdump`: `Ctrl+C`.

Короткий список «порты Xbox» (TCP 53, 80, 3074 и UDP 88, 500, 3544, 4500) эти соединения не покрывает. UDP служба не проводит.

## Журнал

Смотреть живые строки:

```bash
journalctl -u egress-proxy -f
```

Последние 100 строк: `journalctl -u egress-proxy -n 100 --no-pager`. Выход из живого журнала: `Ctrl+C`.

Как читать строки:

- `DNS имя A -> АДРЕС_VPS` — приставка спросила адрес, сервер назвал себя.
- `Прокси имя:443 -> … с адреса АДРЕС_VPS клиент=АДРЕС_ДОМА` — соединение ушло с сервера. Сайт видит сервер.
- `закачка напрямую` — файл игры идёт с дома, мимо сервера.
- `Отказ DNS клиенту …` — этот адрес спросил DNS, а в `ALLOW_CLIENTS` его нет.
- `AAAA -> пусто, через прокси IPv6 нет` — у сервера нет IPv6, приставка идёт по IPv4. Для работы это нормально.

Служба не поднялась:

```bash
systemctl status egress-proxy --no-pager
```
