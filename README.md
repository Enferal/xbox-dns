# Кратко, для Ubuntu

Три инструкции, от короткой к самой подробной:

1. [README.md](README.md) — коротко, если команды уже знакомы
2. [README_EASY.md](README_EASY.md) — простыми словами
3. [README_STUPID.md](README_STUPID.md) — куда нажимать, по шагам

Репозиторий: https://github.com/Enferal/xbox-dns

Код под лицензией MIT: [LICENSE](LICENSE).

Ubuntu 22.04 или 24.04. Устройство ходит в интернет через DNS этого VPS. Имена из списка открываются на сервере, и сайт видит его адрес. Всё остальное идёт мимо VPS. Интернет самого сервера скрипт не трогает.

Пустой `ALLOW_CLIENTS` пускает всех. Впишете адреса — ответит только им.

Дома два разных случая. Команды OpenWrt вводите на роутере: приглашение там `root@OpenWrt`, не на VPS. Ошибка `0x800704c6` и проверка после перезагрузки — в [ROUTER.md](ROUTER.md).

Обычный роутер. В DNS устройства впишите адрес VPS. До него должны проходить UDP и TCP 53, TCP 80 и 443. Для этого устройства выключите родительский контроль, подмену DNS, прозрачный прокси и VPN на всю сеть. С компьютера в той же сети `nslookup user.auth.xboxlive.com АДРЕС_VPS` должен вернуть адрес VPS.

Роутер на OpenWrt. Одного DNS мало: после перезагрузки приставка снова может показать `0x800704c6`.

- Zapret ломает TCP 443, пока адреса VPS нет в наборе `nozapret`. Допишите его в файл и в живой набор: `grep -qx АДРЕС_VPS /opt/zapret/ipset/zapret-ip-user-exclude.txt || echo АДРЕС_VPS >> /opt/zapret/ipset/zapret-ip-user-exclude.txt`, затем `nft add element inet zapret nozapret '{ АДРЕС_VPS }'`. UDP 443, который zapret уже закрывает, не открывайте: сервис принимает только TCP.
- Старый Xray забирает весь TCP приставки на `127.0.0.1`, если `iptables -t mangle -S XRAY` показывает `TPROXY` с её MAC. Снимите правило: в строке замените `-A` на `-D`. Потом выключите скрипт в файрволе. У секции с `path='/etc/firewall.xraytproxy'` поставьте `enabled='0'` через `uci set` и `uci commit`. Сам файл не удаляйте.

## Что должно быть на сервере

Ubuntu 22.04 или 24.04, вход root, systemd. Пакеты: `python3`, `iproute2` (это `ip` и `ss`), `ca-certificates`, `bind9-dnsutils` (это `dig`), `ufw`, `git`.

После вопросов установщик сам смотрит этот список. Нет пакета — ставит и пишет `Ставлю недостающее`. Всё уже стоит — пишет `Все нужные пакеты уже стоят` и `apt` не трогает. Другую систему и другую версию Ubuntu он не ставит.

`git` нужен ещё до скрипта, иначе репозиторий не скачать. Команда ниже ставит его, если его нет. Остальное поставит установщик.

## Перед установкой

Порты 53, 80 и 443 должны быть свободны:

```bash
ss -tulpn 'sport = :53 or sport = :80 or sport = :443'
```

Строка `127.0.0.53:53` от `systemd-resolved` не мешает. Строка `*:443` или `0.0.0.0:443` значит, что порт занят. DNS поднимется, а сайты через VPS не откроются, пока эта программа работает.

## Установка

На сервере:

```bash
ssh root@IP_VPS
apt-get update
apt-get install -y git
git clone https://github.com/Enferal/xbox-dns.git /opt/egress-proxy
cd /opt/egress-proxy
sh deploy/install-native.sh
```

Первая строка на экране: `Установщик egress-proxy. Пустой ALLOW_CLIENTS пускает всех.` Если вместо неё сразу пошёл список пакетов, запущен не этот репозиторий. Пакеты скрипт проверяет после вопросов.

Скрипт ставит службу `egress-proxy`. В первый раз берёт домены Xbox из `config/allow-destinations.xbox.txt` и открывает входящие SSH, 53, 80 и 443. Если правила для 53, 80 и 443 уже есть, показывает их и спрашивает. Enter оставляет файрвол как есть. `адреса` убирает разрешения для всех и оставляет только правила с адресом. `все` открывает эти порты заново. В конце печатает адрес, который надо вписать как DNS.

Позже, когда в репозитории появятся новые файлы:

```bash
cd /opt/egress-proxy
git pull
sh deploy/install-native.sh
```

Если в `/etc/egress-proxy` уже что-то лежит, первый вопрос: `Удалить прошлые настройки? [y/N]`. Enter оставляет `egress.env`, список доменов и `exit-ips.txt`. `y` стирает эти три файла и кладёт примеры заново.

Дальше вопросы по одному. У каждого есть пример и строка «Сейчас». Enter оставляет «Сейчас». Один вопрос другой: у `DNS_UPSTREAM` Enter подставляет DNS самого VPS, из `/run/systemd/resolve/resolv.conf` или `/etc/resolv.conf`. Адреса `127.0.0.53` туда не попадают. Если в файле был другой список, скрипт напишет «В файле сейчас». Чтобы оставить его, введите его руками. Своих DNS на VPS нет — Enter оставит `1.1.1.1,8.8.8.8`.

| Переменная | Зачем | Enter |
| --- | --- | --- |
| `LISTEN_IP` | На каком адресе слушать. `0.0.0.0` — на всех. Рядом скрипт показывает адрес этого VPS. | как сейчас, или `0.0.0.0` |
| `DNS_PORT` | Порт DNS, его указывают на устройстве. | как сейчас, или `53` |
| `PROXY_PORTS` | Порты сайтов, через запятую. | как сейчас, или `80,443` |
| `DNS_UPSTREAM` | Куда VPS сам спрашивает настоящие адреса сайтов. | DNS этого VPS |
| `MAX_WILDCARD_DEPTH` | Сколько лишних меток покрывает имя из списка. `4` — это `a.b.c.d.example.com`. | как сейчас, или `4` |
| `ANSWER_TTL` | Сколько секунд устройство помнит ответ DNS. | как сейчас, или `60` |
| `ALLOW_CLIENTS` | Кто может спрашивать этот DNS. Пусто — кто угодно. В примере может быть адрес вашего SSH. Знак `-` тоже пускает всех. | как сейчас; на чистой установке пусто |

## Кто может стучаться

Файл на сервере: `/etc/egress-proxy/egress.env`.

```bash
ALLOW_CLIENTS=203.0.113.8,198.51.100.0/24
```

Пустая строка пускает всех. Если вписать адреса, остальные увидят в журнале `Отказ DNS клиенту …`. После правки:

```bash
systemctl restart egress-proxy
```

## Устройство

В сети устройства укажите DNS из последней строки установки. Прокси на устройстве не нужен.

Проверка прямо на сервере:

```bash
dig +short @127.0.0.1 user.auth.xboxlive.com A
```

В ответе должен быть адрес этого VPS.

## Домены

Список лежит в `/etc/egress-proxy/allow-destinations.txt`.

Строка `xboxlive.com` покрывает само имя и поддомены до 4 меток, в том числе `user.auth.xboxlive.com`. Закачка игр сюда не входит. Имена из `/etc/egress-proxy/direct-destinations.txt` (`dl.delivery.mp.microsoft.com`, `assets1.xboxlive.com` и соседние) получают настоящий адрес сети доставки, файл идёт с домашнего IP. Вход, магазин и лицензии остаются на VPS. После правки списка:

```bash
systemctl restart egress-proxy
```

В примере Xbox ещё есть `xbox.com`, `xboxservices.com`, `gamepass.com`, `bing.com`, `microsoft.com`, `akamai.net`, `akamaized.net`, `live.com`, `microsoftonline.com`, `msauth.net` и `msftauth.net`. Зоны Microsoft, Bing, Akamai и страницы входа общие: через VPS пойдёт любой сайт на этих именах. Не нужно — удалите строки и перезапустите службу.

Через сервис идёт TCP 80 и 443. UDP, в том числе часть трафика Xbox, мимо.

## Журнал

Новые строки сразу:

```bash
journalctl -u egress-proxy -f
```

Последние 100:

```bash
journalctl -u egress-proxy -n 100 --no-pager
```

За 10 минут:

```bash
journalctl -u egress-proxy --since "10 min ago" --no-pager
```

`Отказ DNS клиенту …` — этот адрес спросил DNS, а в списке его нет. `Прокси user.auth.xboxlive.com:443 -> …` — запрос ушёл с VPS. Служба не поднялась:

```bash
systemctl status egress-proxy --no-pager
```
